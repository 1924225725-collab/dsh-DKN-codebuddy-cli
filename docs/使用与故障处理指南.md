# 使用与故障处理指南

[English](USER_GUIDE.en.md) · [安装说明](安装教程.md) · [日志入口](反馈与日志.md) · [返回首页](../README.md)

适用于 0.3.2。插件配置页中的“故障处理与使用指南”提供离线可读的要点；本页是完整说明。以下示例均为虚构情景。

## 先确认失败发生在哪一步

插件把模型回复转换成 DSH 文字与工具请求，文件和命令仍由 DSH 执行。最终回复失败，并不会撤销此前已经完成的工具操作。重试前先查看 DSH 的工具记录、实际文件内容和命令退出码。

如果错误提示“本次结果未交付工具调用”，指的是报错的这一次模型结果；不能据此认定整个多步骤任务没有修改过文件。插件不会因格式错误自动重新请求模型或重跑工具。

## 常见提示与处理方法

| 提示或现象 | 什么情况下会出现 | 建议处理 |
| --- | --- | --- |
| CLI_STRUCTURED_OUTPUT_MISSING | 官方 CLI 没有返回原生 structured_output | 核对插件/CLI 运行版本和模型，导出普通日志，用短问题验证；不使用普通文字替代。必要时按官方安装流程更新 CLI |
| native-final-results | 最终 CLI 记录不唯一 | 插件不会选择最后一份；保留日志与诊断 ID 后反馈 |
| native-envelope 或字段错误 | 原生结果为字符串、包装、不完整对象或字段错误 | 不补缺失内容。缩短单次输出并反馈诊断 ID |
| 旧 ambiguous-json / possibly-truncated-json | 保存的旧调用使用文字协议 | 核对运行 0.3.2 并复现新调用；升级不会改写旧会话错误 |
| `TOOL_CALL_INVALID` | 工具名没有声明，或工具参数不是有效对象 | 确认当前 DSH 工具已启用，并把任务写清楚。不要将未知名称改成某个相近工具后执行；反馈所用 DSH/CLI/插件版本 |
| 最后提示失败，但命令已有输出 | 工具已成功，随后模型汇总或下一步回复失败 | 查看输出、退出码和文件状态；如果只缺总结，明确请求“仅汇总已提供的结果，不重复操作” |
| 代码块、引号或路径不完全一致 | 模型可能多写、少写转义字符或改动了文字 | 只要求重写有差异的一小段并逐字符核对。插件不会对合法 text 统一二次反转义；不要直接执行未经确认的内容 |
| `CLI_AUTH_REQUIRED`、401 | 官方 CLI 的登录或授权失效 | 从配置页复制官方登录命令，在 CLI 按官方流程执行 `/login`，再验证一次短请求。插件不能恢复账号权限或额度 |
| `CLI_TIMEOUT` | 整次 CLI 调用超过设置时限，包含启动、模型处理与进程退出 | 拆分任务，检查官方服务与网络，按需提高总时限。增加时限不能解决冲突 JSON；重试前仍要确认此前操作 |
| 文件找不到、`grantWrite`、ACL 或权限错误 | 工作区选错、路径不存在，或 DSH/Windows 工具环境拒绝访问 | 先在资源管理器核对工作区和路径，按实际 DSH 权限策略处理。不要把权限错误直接归为模型格式错误，也不要为修复格式而修改权限 |

## 原生输出的边界

只接受官方 structured_output 对象，且必须恰好含 text 与 toolCalls。文字字段不扫描额外协议片段；工具名必须已声明，参数必须是对象。当前调用不再进行字符串/包装恢复、缺字段推断或文字转义修复。

StructuredOutput 是允许的输出工具，CLI 文件、命令及 MCP 业务工具仍关闭，由 DSH 执行业务操作。多个最终记录会拒绝；同一提交计划内的重复操作保留。

插件不额外启动 CLI 修复，官方结构化处理允许有限内部轮次，可能产生多次模型请求和用量。网络、登录、限额、截断或不合法结果仍会失败；结构正确不保证任务意图正确。

## 长对话中减少再次失败

历史会话同时包含代码、工具结果、旧指令和多次失败时，模型可能难以保持输出约束；长历史只是影响因素之一，不是每次失败的已证实根因。反复失败时，新建对话并提供简短、准确的任务摘要：已完成什么、当前文件在哪里、哪些操作不能重复、下一步只做什么。不要仅靠不断发送继续来反复触发同一任务。

一次处理一个清楚的动作或小批次。需要长文件时，先规划再分段读改，避免要求一次输出全部文件。以上做法减少负担，但不保证特定模型永不出错。

## 如何保留能定位问题的日志

1. 在插件 `dsh-codebuddy-cli-cn` → 组件 `llm-codebuddy-cli-cn` 配置页找到“诊断日志与问题反馈”，记录运行版本。
2. 导出普通日志，附完整错误、诊断 ID、时间、模型与推理设置，以及复现步骤。普通日志不保存聊天或回复正文。
3. 需要查看原始模型返回时，先阅读提示并手动开启“采集下一次失败回复”，再复现一次。无法补录开启前的原文。
4. 成功调用和主动停止任务不消耗采集机会；下一次非主动取消的失败会结束本次采集。取消采集、清空日志或重启也会关闭开关。没有模型正文的启动/登录错误可能无法产生详细样本。
5. 预览详细样本，检查导出文件中的全部内容并移除私人信息后再分享。详细样本最多 256 KiB，超出保留首尾；标记为截断的样本不代表日志里有完整原文。日志不会自动上传。

看到错误后先保留证据，再决定重试。不要以“后来成功了一次”替代对原失败原因的核对。

## 图片提问

升级并重启 DSH，刷新模型目录，选择配置页“图片输入”列标记“图片”的模型，在 DSH 的附件入口上传图片后提问。例如：“请说明附图中的界面问题。”随后可继续问上一张图片。图片会随请求发送到官方模型服务，日志不会保存图像内容。

优先 PNG/JPEG。最多保留 5 张请求图片，转换后每张 ≤2 MiB、最长边 ≤1920；Base64 合计 ≤8 MiB，总请求 ≤20 MiB。大图会按 DSH 附件接口转换，小字可能因此变得模糊，必要时上传局部清晰截图。WebP/GIF 依赖 DSH 转换及模型支持，不保证动图逐帧识别。支持 DSH 工具返回的标准图片附件，包括桌面、窗口、区域和浏览器截图；模型原生图片生成尚未适配。

- IMAGE_MODEL_UNSUPPORTED：刷新目录并选支持图片的模型，手填未知 ID 不会自动开启图片。目录声明不等于所有模型已经验证。
- IMAGE_SERVICE_UNAVAILABLE / IMAGE_READ_FAILED / IMAGE_ATTACHMENT_INVALID：更新 DSH，重新启用插件或重新上传；不需要给 CLI 开放文件工具。
- IMAGE_TOO_LARGE / REQUEST_TOO_LARGE：裁剪、缩小图片或减少历史。
- IMAGE_OFFLOAD_REQUIRED：DSH 应记录较早图片的卸载后继续；若未启用该机制，可新建会话只上传本次需要的图片。卸载后模型没有原图，不应让它猜测，重新附图即可。
- CLI_STREAM_INVALID / CLI_PERMISSION_REQUIRED：更新官方 CLI、保存普通诊断日志反馈；插件不会把未闭合帧或交互权限请求自动放行。

含图片历史的失败不采集原文，即使手动开启采集，也只记录该次尝试和统计后关闭开关。反馈提供普通日志、诊断 ID、图片格式/尺寸/张数和问题步骤；只在愿意时另附自行制作的非私人示例图。

## 工具图片结果（0.3.4）

工具返回图片现在与用户上传走同一原生输入通道。保留 toolCallId、isError 和顺序；失败工具附图可供观察，不代表工具执行成功。IMAGE_TOOL_CALL_INVALID 表示截图缺少所属调用 ID。纯路径、网址和 Base64 文字不会被自动读取。CLI 错误帧会归类为鉴权、目录权限或通用请求失败。各类工具的接入条件与尚未支持的返回类型见[工具与返回内容适配范围](工具适配范围.md)。
