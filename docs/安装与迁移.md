# 安装与迁移：1.0.3 整合版

1. 在旧版配置页记下各自的CLI路径、登录配置目录、默认模型、推理强度和超时。只记录配置，不导出或复制Token、Cookie或密码。
2. 等待进行中任务结束，在DSH插件管理中停用 dsh-codebuddy-cli-cn、dsh-codebuddy-cli-intl，以及此前0.4.4预览的 dsh-codebuddy-cli。保留旧安装包，不删除官方登录或独立账号目录。不要求卸载用户数据。
3. 安装 dsh-dkn-codebuddy-cli-1.0.3.tgz。若DSH要求重新加载或重启，按正常流程操作；本地整合版不承诺无重启热更新。
4. 左侧栏进入 DKN CodeBuddy，分别检查国内、国际页的运行版本均为1.0.3。检查原配置是否仍在；如果为空或不同，在相应区域恢复第1步记录并保存。两侧设置不通用。
5. 国际默认CLI配置目录沿用 ~/.dsh-codebuddy-cli-intl；国内未指定目录时使用官方国内默认，不继承外部的 CODEBUDDY_CONFIG_DIR。过去依赖该环境变量的用户应在国内“登录配置目录”显式填写原值，避免改变所用CLI配置。这里只是配置选择，不自动迁移身份。
6. 独立账号目录保留 LOCALAPPDATA/dsh-codebuddy-cli-cn/accounts 和 LOCALAPPDATA/dsh-codebuddy-cli-intl/accounts；备注、模型前缀仍区分区域。不复制凭据，不自动轮换账号。默认模式不承诺凭据物理隔离；要隔离账号应使用各自独立环境。
7. 分别刷新目录，在新会话选择明确标记国内或国际的提供方。页面顶部选择不会改变正在运行或已有会话的区域。
8. 确认新会话正常后，再在无副作用的旧会话中检查续接。保留旧provider ID和模型ID是兼容基础，不代表本轮已验证所有profile/旧会话迁移。

若提示 DUPLICATE_ADAPTER 或配置命名冲突，先检查旧插件是否仍启用，停止依赖后续步骤。不要靠删除账号文件解决。

若不能使用，先停用合并版，再启用原独立版及恢复已记录配置。不要让两者同时注册同一提供方。合并版不改写旧账号/登录文件，回退仍需核对DSH的profile设置。

诊断、账号管理和指南按区域分开。普通诊断JSON可与错误时间、完整提示、提供方和实际版本一起反馈；详细样本分享前必须自行检查。合并不会解决上游401、额度不足、网络不可达或未定位的bug005—008。
