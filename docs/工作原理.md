# 工作原理

**简体中文** · [English](ARCHITECTURE.en.md) · [返回首页](../README.md)

0.3.1 将官方 CodeBuddy CLI 国内版适配成 DSH 模型提供方。DSH 保存历史、管理权限并执行业务工具，插件整理模型输入并校验官方结构化结果。

## 请求与结果

每次请求把 DSH 的消息、系统要求、当前工具定义及 responseSchema 交给本机官方 CLI。使用 --print --output-format json --json-schema，工具白名单仅含 StructuredOutput；关闭其他 CLI 业务工具、MCP、自动记忆和会话持久化。

StructuredOutput 是官方输出工具，用来提交 text 和 toolCalls 两字段对象，并不读取或修改项目。插件只接收官方最终记录的 structured_output 对象，不从 result 普通文字中提取或猜测 JSON。文字中的代码、路径或协议示例都作为字段内容保留。

原生字段缺失、包装或字符串对象、额外字段、不合法工具名/参数，以及多个最终记录都会失败，不执行文字回退、不选择最后一份。工具参数必须是对象。验证完整结果后再向 DSH 交付，因此失败时不会交付半份工具计划。单一计划里的重复操作保留。

模型请求读取、修改或运行命令时，插件向 DSH 返回工具块；DSH 自己执行并将结果加入历史，下一次调用再携带该历史。最终回复失败不会撤销之前的工具，重试前需检查实际状态。上下文由 DSH 承担，目前只接收文本。

## 时限与用量

每个 DSH 请求启动一次 CLI，原生结构化处理最多允许 4 个 CLI 轮次，仍受整次调用总超时及用户取消约束。该上限不是计费请求次数的保证。插件不启动额外 CLI 修复或自动重试，官方处理本身仍可能包含内部多次模型请求；Token 与额度以官方返回和用量页面为准。

## 登录、目录和安装

官方 CLI 使用通过其正式流程登录的国内账号，插件不接收或复制密码、Cookie 或 Token。可选配置目录只作为路径传递。对话会发送到官方模型服务。

另一条只读 ACP 流程通过 initialize 和 session/new 获取模型、积分倍率、推理选项及上下文信息；不发送模型问题。启动、每 15 分钟与手动刷新会更新目录。目录可见不等于所有模型对当前账号都有权限或均已实测，倍率也不是剩余额度。

一键配置查找当前用户的已有安装；缺少时使用官方安装器或官方 npm 包。登录仍由官方 CLI 完成，不写死开发者路径。

## 验证与反馈

60 项自动检查和新适配器三次官方 CLI 合成联调通过；工具结果是模拟数据，没有运行真实 DSH 项目工具。全部模型、全新电脑与其他系统完整流程尚未逐一验证，不保证所有模型输出总是成功。

普通日志不含正文，详细失败结果只在用户主动开启采集后保存；不自动上传。参阅[日志说明](反馈与日志.md)与[故障指南](使用与故障处理指南.md)。
