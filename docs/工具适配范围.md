# 工具与返回内容适配范围

[English](TOOL_COMPATIBILITY.en.md) · [返回首页](../README.md)

适用于国内版 0.3.4。插件读取 DSH 当前声明的工具名称与参数，没有按“桌面截图”“浏览器截图”等名称建立白名单。DSH 负责执行、权限和结果归档；插件负责把已有结果发给模型。新增图片支持不等于安装了截图工具。

| 工具或结果类型 | 当前支持范围 | 尚需注意的部分 |
|---|---|---|
| 读取、修改、命令、搜索等普通工具 | 传递 DSH 的工具定义、调用与文字结果 | 工具本身是否安装、可运行或获准由 DSH 决定，并非逐一实机验收所有工具 |
| 桌面、显示器、窗口、区域截图 | 0.3.4 支持工具返回的标准图片附件 | 具体能截哪个屏幕或窗口由截图工具决定；插件不主动捕获屏幕 |
| 浏览器页面、元素、长页面截图 | 同样支持标准图片附件，不限制工具名 | 超长图片缩放后小字可能模糊，优先分区或裁剪 |
| 读取图片、渲染图表、PDF 页面转图片 | 结果为标准图片附件时支持 | PDF 等二进制文件需先由工具读取或渲染，不能把文件路径当作图片 |
| MCP 或第三方工具返回图片 | 经 DSH 转为标准图片附件后支持 | 未归一化的 MCP/raw Base64/自定义对象不直接作为图片发送 |
| 仅返回本地路径、图片网址、data URL 或 Base64 文字 | 保留为文字结果 | 不主动读路径或下载网址；请使用 DSH 的读取图片工具转成附件 |
| PDF、Word、Excel 等原始文件 | 可使用 DSH 工具返回的文字或页面图片 | 无直接把这些文件二进制交给 CLI 理解的原生通道 |
| 原生音频、视频、实时画面流 | 尚未适配 | 工具转写成文字或抽帧为标准图片后，分别按文字/图片处理 |
| 模型直接生成图片、助手消息中的图片输出 | 尚未适配 | 不影响 DSH 中独立生成工具的执行；其标准图片结果可作为工具观察输入 |

## 工具截图如何传入模型

标准返回形式是 DSH 的 `role: 'tool'` 消息，含非空 `toolCallId`，内容数组含 `{ type: 'image', attachment: ImageAttachmentRef }`。图像必须由 DSH 附件服务提供，不能只伪造一个文件名或 URL。图片转换和读取通过 `attachments.readImageRequest` 完成。

工具 ID、图片顺序、旁边的文字与 `isError` 均保留。失败工具附有图片时，模型可观察已返回内容，但不能把工具标为成功。用户上传图和工具图一起计算预算：最多保留 5 张，每张转换后 ≤2 MiB、最长边 ≤1920；Base64 总计 ≤8 MiB、完整请求 ≤20 MiB。超预算交 DSH 卸载较早图片，不静默删除历史。

插件通过本机 CLI 将图片发送给官方模型；插件诊断日志不保存图像、Base64 或详细失败回复。模型必须在动态目录声明图片输入能力。

## 遇到问题

- 旧版报“工具截图尚未适配”：升级并重启，确认运行版本为 0.3.4。
- `IMAGE_TOOL_CALL_INVALID`：工具图片消息缺少调用 ID，请更新产生结果的工具或桥接插件，不改图为用户消息来冒充来源。
- `IMAGE_MODEL_UNSUPPORTED`：刷新目录并选支持图片的模型。
- `IMAGE_READ_FAILED`：附件可能失效；重新执行截图工具。不会改用任意路径读取。
- `IMAGE_OFFLOAD_REQUIRED`：DSH 应卸载较早图片；如果当前环境未启用该机制，减少本轮图片或新建会话。
- `CLI_LOCAL_PERMISSION_DENIED`：检查官方 CLI 配置、缓存目录的本机访问权限。CLI 自身不能启动模型请求时，插件版本检查仍可能通过。

## 验证范围

79 项自动检查通过，覆盖工具来源、混合历史、卸载、取消、错误帧、原生输出与日志隐私。使用官方 CLI 2.174.0 / deepseek-v4.1-flash，通过真实适配器验证了合成工具图片、用户图与工具图的区分，以及失败工具附图三种情况。附件服务是隔离测试实现，没有捕获用户真实桌面，也没有逐一执行桌面、浏览器和第三方截图工具；这些实际 DSH 工具链路仍需定向验收。
